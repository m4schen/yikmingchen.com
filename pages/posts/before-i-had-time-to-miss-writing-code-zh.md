近日读到两篇文章，intlsy 的[《我不得不把才华埋葬在昨天》](https://mp.weixin.qq.com/s/zk0KxuLzhmMJ4LPYW_OHMA)和 Obie Fernandez 的 [You're Already a Meat Proxy](https://x.com/obie/status/2101779116056088732)，私以为非常值得分享，也聊聊自己当下的一些浅见。我能理解将越来越多的工作交给 agent 后，失去亲手完成某件事的乐趣所带来的遗憾。AI 给软件工程带来的变化可能是这二十年来最大的。

在 LLM 从只能进行简单对话，到在不少编程任务上超越 Junior 的这段时间，我正好在读我的本科。大二的时候，GPT 甚至不能稳定地帮我写出一个正常运行的简单网页；到了大四，我已经看着各家模型在 IOI 题目的独立评测中拿到满分。我自己也从遇到 bug 时 Google 或者翻阅 Stack Overflow 到现在甚至很少逐行阅读代码。

**作为在 AI 时代毕业的 Junior，我没有多少才华可供我埋葬在昨天**。我没有经历过一个足够长的、需要完全依赖自己编写代码的工程生涯，在我还没有完全长出自己的 Taste 时，这个领域就已经大变天了。而且作为人我的迭代速度远不及 AI。

我的能力和经验还不足以让我判断前 LLM 时代的哪些审慎值得坚守，就已经不得不放任 Agent 编写代码。

我能做的也只是从现在的 Staff Engineer 的 Agent Skill 中借鉴一些自己尚未形成的工程判断。在每个人都被 expected to be more productive 的当下，我没有办法不做 Agent 的“机甲驾驶员”，无论是从什么角度来说。

我觉得论代码质量，我早就不是 Agent 的对手了，使用 Agent 对我来说起码不会产生更差于我手写的效果。我考虑不到的边界情况可能 AI 还想得全一些，或者是至少考不可能少于使用者，那难道我还要自己手写一些垃圾来占用给我做 Code Review 的人的时间（或者浪费 token）吗？使用 Agent 并且尽可能地完善 verification loop 已经是我能尽的最大努力了。**至少在工业生产的语境下，我觉得争论代码是否应该手写，和争论衣服是否应该手洗是等价的**。至于有人是否享受亲手洗衣服的过程，那是另一个问题。

我当然理解兴趣、特长和工业界需求恰好重合时，能够带来多么巨大的满足感。但这种重合或许本来就是一种幸运，而不是能够被长期保证的状态。可以继续享受织毛衣的过程，只是未必还能期待这件事始终能创造同样的商业价值。工业界的热点始终在漂移——二十年前是网站，十年前是移动端，现在是 AI——而个人兴趣未必能以同样的速度变化。或许不应该太期待个人的兴趣、擅长的方向和工业界的需求能够长期重合。我并不是说过去的快乐不值得怀念，只是我不觉得我们有太多可选择的余地。

很悲哀也可以很幸运地说，我至少到现在也没找到可以让我喜欢到能干一生的方向，我的兴致总是来得很快也消散得很快，在这个方面来说我甚至很庆幸现在有如此强大的工具，可以让我在我的兴致消失前产出些什么。

当 AI agent 成为主要的代码编写者的当下，我们还应该继续以人类阅读体验为中心进行优化吗？那些为了降低理解成本而引入的额外接口和抽象层还值不值得继续存在呢？或许很多软件工程的一贯原则在当下值得重新审视。

以前我们可以通过大量手写代码、调试和重构逐渐形成自己的 Taste，而我或许还没来得及积累足够多的经验，就已经开始把实现交给 Agent。

那些在旧的工作方式中获得的工程直觉，究竟是会被新的 verification 能力取代，还是会成为像我这样成长起来的工程师始终缺失的东西？

我暂时也没有答案。
